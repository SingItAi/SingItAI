# API-ключи SingIt — план

*Черновик от 14 октября 2026. Основа: `singitai/main` @ `ece4081` + ветка `feat/ask-discovery`.*

## Зачем

Сейчас платные модели SingIt может оплатить только программа с криптокошельком и x402-библиотекой. Обычный
программист так не работает: он берёт OpenAI SDK и вставляет ключ. Ключ SingIt должен дать ему ровно это:

```python
from openai import OpenAI
client = OpenAI(base_url="https://app.singitai.app/v1", api_key="sk_singit_…")
client.chat.completions.create(model="claude-opus-5.5", messages=[{"role": "user", "content": "Hello!"}])
```

Каждый ответ оплачивается **из кошелька владельца ключа через его лимиты**, как в веб-агенте: USDC остаются у
него, лимитер на Base не даст потратить больше дневного лимита, ключ отзывается одной кнопкой.

**Чем это лучше BlockRun.** У BlockRun ключ привязан к балансу, который лежит у них. У SingIt ключ — лишь
разрешение тратить из кошелька пользователя в пределах лимитов в контракте. Утечка ключа ограничена дневным
лимитом и отзывом, а не всем балансом.

## Что уже есть и переиспользуется

| Что | Где | Как используется |
|---|---|---|
| Ответ модели с оплатой из лимитов | `web_ask.chat()` | Ядро ключевого эндпоинта: потолок под лимит на покупку, Base через `ask_metered`, Solana через `ask_solana`, без повторных оплат |
| Разбор неясных оплат | `ask_metered.recover`, `ask_solana.recover` | Пока оплата не разобрана, ключ, как и аккаунт, не платит снова |
| Лимиты аккаунта | `agent_allowance.py` (Base), `solana_allowance.py` | Жёсткий потолок трат ключа |
| Каталог моделей и цены | `ask_catalogue.py` | Проверка `model`, расчёт потолка |
| Аккаунты, сессии (хэш токена), одноразовые nonce для подписи | `web_accounts.py` | Ключи хранятся так же, только хэш; создание подтверждается подписью кошелька |
| Ограничение частоты покупок | `gw._enforce_user_purchase_rate` | Плюс отдельный лимит запросов на ключ |
| Push-уведомления | `web_push.py` | Оповещение о новом ключе и необычных тратах |
| Остановка всех платежей | `gw._purchases_paused` | Действует и на ключи |

## Как будет устроено

### Ключ

- Формат `sk_singit_` + 32 случайных байта (base64url). Показывается **один раз** при создании.
- Хранится только `sha256`. В списке виден префикс: `sk_singit_Ab3x…`.
- Таблица `api_keys` в базе `WebAccountStore`:

| Поле | Смысл |
|---|---|
| `key_hash` | sha256 ключа, первичный ключ |
| `key_id` | короткий публичный id для управления и журнала |
| `account_id` | владелец (`wallet:…` или `solana:…`) |
| `name` | название от пользователя («мой бот») |
| `prefix` | первые символы для узнавания в списке |
| `daily_cap_atomic` | дневной лимит ключа, не больше дневного лимита аккаунта |
| `per_request_cap_atomic` | потолок на один ответ, не больше лимита на покупку |
| `scopes` | на старте только `chat`; позже `services`, `shop` |
| `created_at`, `expires_at` | срок по умолчанию 90 дней |
| `last_used_at`, `revoked_at` | использование и отзыв |

- Траты по ключу пишутся в `user_event_store` с `key_id`: так считаются его дневная сумма и история.

### Создание и отзыв (приложение app.singitai.app)

- Новый раздел «Developers → API keys»: список ключей (название, префикс, траты сегодня из лимита ключа,
  последний вызов, срок), кнопки «Создать» и «Отозвать».
- **Создание подтверждается подписью кошелька**, как вход: подписывается сообщение «Create API key "<name>",
  up to $X a day, until <date>». Чужая открытая сессия не сможет тихо выпустить ключ.
- Отзыв — без подписи, мгновенно: отключать доступ должно быть легко.
- После создания — push «Создан API-ключ "<name>"».

API приложения (сессия + CSRF, как остальной `/web/v1`):
- `GET /web/v1/api-keys`
- `POST /web/v1/api-keys/nonce` → сообщение для подписи
- `POST /web/v1/api-keys` с подписью → ключ, показанный один раз
- `DELETE /web/v1/api-keys/{key_id}`

### Публичный эндпоинт в формате OpenAI

- Адрес: **`https://app.singitai.app/v1`**. Его отдаёт тот же процесс `web_api`, что и приложение, поэтому
  настройка Cloudflare не нужна; `api.singitai.app` можно добавить позже как синоним.
  `ask.singitai.app` остаётся x402-продавцом для агентов со своими кошельками.
- `POST /v1/chat/completions` с `Authorization: Bearer sk_singit_…`:
  1. найти ключ по хэшу; проверить срок, отзыв, scope;
  2. проверить лимит запросов ключа и его дневной лимит;
  3. `model` из запроса: id из `/v1/models` (`claude-opus-5.5`) или без поля — модель по умолчанию; внутри
     превращается в `ask:<id>`;
  4. вызвать `web_ask.chat()` с этой моделью и `max_tokens` (сейчас модель берётся из сессии веб-чата —
     добавить параметр, остальное без изменений);
  5. вернуть ответ в формате OpenAI: `id`, `object`, `created`, `model`, `choices`, `usage` и `billing`.
- `GET /v1/models` — тот же список, что у `ask.singitai.app`.
- Ошибки в формате OpenAI (`{"error": {"message", "type", "code"}}`), чтобы SDK показывал их как есть:

| Ситуация | HTTP | `type` |
|---|---|---|
| Нет ключа или неверный | 401 | `invalid_request_error` / `invalid_api_key` |
| Ключ отозван или истёк | 401 | `invalid_api_key` |
| Дневной лимит ключа или аккаунта исчерпан, лимиты не выданы | 429 | `insufficient_quota` (текст: что именно и как поднять) |
| Ответ дороже лимита на покупку | 400 | `invalid_request_error` (текст: какой потолок нужен) |
| Предыдущая оплата ещё не разобрана | 409 | `payment_pending` |
| Платежи остановлены | 503 | `service_unavailable` |
| Модель недоступна | 404 | `model_not_found` |
| `stream: true` (этап 1) | 400 | «streaming is not offered yet» |

### Безопасность

- В базе только хэши. Ключ не пишется в логи, заголовок `Authorization` маскируется.
- Ключ умеет только задавать вопросы моделям. Менять лимиты, выводить деньги, покупать карты он не может.
- Ущерб от утёкшего ключа ограничен: лимит ключа, лимит аккаунта в контракте, срок, отзыв в один клик.
- Push владельцу, если ключ потратил больше половины своего дневного лимита.
- Запросы с заголовком `Origin` отклоняются: ключ для серверного кода, в браузере его не должно быть.
- Отдельный лимит частоты на ключ, например 60 запросов в минуту.

## Этапы

### Этап 1 — ключи и эндпоинт (основное)

1. `api_keys` в `WebAccountStore`: создание, поиск по хэшу, отзыв, учёт трат.
2. `web_ask.chat()` принимает модель параметром.
3. Обработчик `/v1/chat/completions` и `/v1/models` для `api.singitai.app`.
4. API приложения для ключей с подписью при создании.
5. Тесты на подделках лимитера и продавца, как сейчас в `test_web_ask*.py`: верный ключ платит и отвечает;
   отозванный, истёкший, чужой — 401; лимит ключа — 429; неясная оплата блокирует; повтора оплаты нет;
   ключ не попадает в логи.

**Готово, когда** OpenAI SDK с ключом получает ответ от Claude Opus 5.5, а сумма видна в истории аккаунта
с названием ключа.

### Этап 2 — экран в приложении

Раздел «API keys» в `website/app`: список, создание с подписью, показ ключа один раз с кнопкой копирования,
отзыв. Push о новом ключе.

### Этап 3 — выкатка и сайт

1. Выкатка `web_api` (ключи, `/v1`, экран приложения) и gateway (действия `api-chat`, `api-models`).
2. Перезапуск gateway. Перезапуск gateway прерывает покупки на лету, поэтому в тихий момент и по
   `docs/operations.md`; перезапуск через sudo делает владелец.
3. На `/developers`: пример на Python с ключом для платных моделей, карточка «API keys» становится **Live**.

### Этап 4 — совместимость и удобство

1. `stream: true`: отдавать готовый ответ одним SSE-куском. Многие клиенты включают потоковый режим по
   умолчанию.
2. `GET /v1/usage`: траты ключа за день и месяц.
3. Тот же ключ для MCP-сервера SingIt (Claude Code, Codex, Cursor).

## Решения (14 октября)

1. **Адрес:** `https://app.singitai.app/v1`, без новой настройки Cloudflare.
2. **Создание ключа:** только с подписью кошелька; отзыв без подписи.
3. **По умолчанию:** $5 в день, $0.25 на ответ, 90 дней, 60 запросов в минуту. Пределы: до $1000 в день,
   до $50 на ответ, до 365 дней, до 10 живых ключей на аккаунт.
4. **Сети:** Base и Solana (`web_ask.chat` уже умеет обе).

Реализовано в `sign402_gateway/web_api_keys.py`, `web_accounts.py` (таблицы ключей), `web_api.py` (`/v1`),
`web_ask.py` (`api_chat`, общий `_paid_answer`), `web_internal.py` (`api-chat`, `api-models`) и
`website/app` (Settings → API keys). Тесты: `tests/test_api_keys.py`.
